# Travel Reimbursement Approval Agent

A lightweight GenAI / agentic prototype that reviews employee travel-reimbursement claims against a written policy (`POL-*` rules), calls tools to verify each rule, and returns a structured decision:
`APPROVE`, `PARTIAL_APPROVE`, `REJECT` or `MANUAL_REVIEW`.

Built for the *GenAI Developer Candidate Assignment – Travel Reimbursement Approval Agent*.
Everything lives in a single notebook: **`GayatriVidhate.ipynb`**.

## How it works

```
claim JSON
   |
   v
1. Ground      retrieve relevant POL-* rules  ->  put them in the prompt
   |
   v
2. Plan + act  LLM calls tools (Groq function-calling)   [offline: scripted planner]
   |
   v
3. Guarantee   harness runs any mandatory tool the LLM skipped
   |
   v
4. Decide      deterministic rule engine -> decision, amounts, refs, missing docs
   |
   v
5. Validate    schema + sanity checks; on failure -> MANUAL_REVIEW
   |
   v
structured JSON (9 fields)
```

### Tools

| Tool | What it checks |
|---|---|
| `lookup_policy` | Retrieves the most relevant policy rules (grounding) |
| `check_consistency` | Declared total vs items, dates, purpose, group meals |
| `check_eligibility` | Eligible vs ineligible (POL-CAT-02) vs unknown categories |
| `check_receipts` | Receipt rules POL-RCT-01 / POL-RCT-02 |
| `check_per_diem` | Meals $75/day, lodging $200/night, ground $50/day |
| `check_airfare_class` | Business / first class exception (POL-AIR-01) |
| `check_timeliness` | 30-day submission window (POL-TIME-01) |
| `check_approval_tier` | Total after deductions -> auto / manager / director |
| `detect_duplicates` | Same employee, trip and total, or repeated lines |
| `validate_output` | Final schema and sanity guard |

## Key design choices

- **The LLM plans and explains; code decides.** Money and decisions come from a deterministic rule engine, so an LLM mistake can never silently change a payout. If the LLM disagrees with the rules, the rules win and confidence is reduced.
- **Manual Review over guessing.** Missing receipt, business/first-class fare, total over $2,000, late submission, unknown category or ambiguous/conflicting data all route to `MANUAL_REVIEW`; nothing is paid automatically in those cases.
- **Layered reliability.** Forced mandatory tools, output validation with safe fallback, and automatic fallback to the offline planner on any LLM error.
- **Simple retrieval.** The policy is 12 short rules, so keyword retrieval is used instead of a vector database.

## Assumptions and limitations

- Currency is USD. `units` (nights/days) and `attendees` are read from the claim descriptions in Appendix B.
- Per-diem caps apply to the line total: `cap = rate x units` (spend assumed evenly spread).
- Expense date for the 30-day window = trip end date.
- Approval tiers use the reimbursable total after per-diem and ineligible deductions.
- For `MANUAL_REVIEW` claims, approved and deducted amounts are `0` (only definite POL-CAT-02 deductions would be shown); potential per-diem deductions are described in the explanation.
- Duplicate detection only compares claims inside the notebook.
- LLM mode depends on the Groq model being available.
